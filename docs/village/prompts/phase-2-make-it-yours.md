# Kodama Village, Phase 2: Make it yours (about 4–6 weeks)

Phase 1 is done and passed its gate: villages keep 3+ active members after 4 weeks. Phase 2 makes each village and each kodama feel **owned**:

- Friends decorate their world together.
- Students dress up their kodamas.
- Every focus minute earns Leaves to spend on both.
- The village grows a shared tree when the group studies.
- LINE becomes a channel.

This is where the investment moat comes from.

Read `docs/village/SPEC.md` in full, including its **Status** section, before starting. The spec is the source of truth. If this prompt conflicts with it, or the existing code conflicts with either, stop and ask.

## Design principles for this phase
- **Leaves are earned only by studying.** They can never be bought with money, in this phase or later. This keeps the economy honest and the village about studying.
- **Decorating is quick and joyful,** not a level editor. Placing an item should take 2 seconds.
- **Nothing gets in the way of studying.** Build mode is a separate mode; the Library stays quiet; there are no pop-ups during focus.
- **Calm, not casino.** No loot boxes, no random drops, no streak-shame, no countdown sales.

## Gate this phase must make possible
**Students in villages stay on Desker longer than planner-only students.** Build the cohort comparison in Checkpoint 12.

## Not in this phase
Public villages, payments, course intelligence, Garden course trees, crunch events, voice/video.

## Checkpoint 1: Map versions and the edit pipeline

- Each village's map = its template (version 0, read from the template JSON) plus **placements** (decor items on tiles) stored in `village_placement`.
  - `village_map_version` records a snapshot every 50 edits and on owner request, for restore.
- One server-side function, `applyMapEdit(villageId, edit, actor)`, used by the room for every change:
  - `place {decorId, x, y, rotation}`
  - `remove {placementId}`
  - `move {placementId, x, y}`
  - `rotate {placementId, rotation}`
- **Validation:**
  1. Permission: `who_can_build`, plus "owns this item" for personal inventory (Checkpoint 5)
  2. Inside map bounds
  3. Not on protected tiles (Board area, its 1-tile ring, spawn points, zone doorways, paths marked `protected` in the template)
  4. No overlap with walls or other non-walkable placements
  5. Keeps every zone reachable from the Plaza (run a quick flood fill; refuse if it would block a path)
  6. Under the per-village limit (400 placements)
- **Consistency:** every edit carries `baseVersion`. The room applies edits in order and broadcasts `mapPatch {version, ops}`. An edit based on an old version is still applied if it touches tiles nobody changed since; otherwise it's refused with the current state, and the client shows "Someone just changed that spot".
- After every edit, the room recalculates collision, sit spots (decor can add sit spots, e.g. a cushion) and walkable tiles. Clients update the same way from the patch.
- **Restore:** owner can restore any snapshot (with confirm). Restoring is itself a new version, so it can be undone.

**Tests:**
- Every validation rule
- Concurrent edits on the same and different tiles
- Reachability check
- Restore

## Checkpoint 3: Build mode ⏸ STOP AND LET ME TEST

- **Enter with Ctrl/Cmd + B, or the ⋯ menu → Decorate.** Only for people with build permission; others don't see the option.
  - Your presence shows "Decorating" with a little hammer icon.
  - Your kodama stays in the world, and you can still walk.
- **Decor tray** (bottom panel; bottom sheet on phones):
  - Category tabs + search
  - Items you own (with counts) first, then shop items with prices in Leaves
  - "Village items" tab for shared items (Checkpoint 5)
- **Placing:**
  - Pick an item → a ghost preview follows the mouse, or the tile in front of you on phones.
  - Green = valid, red = invalid, with a short reason ("Blocks the path to the Library").
  - Click/tap to place; R rotates; Esc cancels.
  - Placing plays a soft wooden "tok" and a tiny dust puff.
- **Editing:** click a placed item → a mini menu: Move · Rotate · Put away (back to its owner's inventory) · Edit sign text (signs only).
- **Undo/redo:** Ctrl+Z / Ctrl+Shift+Z for your own edits this session (up to 50). Undo is just another edit through `applyMapEdit`.
- **Live co-building:** others' ghosts are visible with their name in small text, so friends can see what each other are doing. Edits appear for everyone instantly with a little pop.
- **Owner tools:** Snapshots (list + restore), "Reset to template" (confirm by typing the village name), and a permission setting: who can build = owner / owner+admins / everyone.
- **Studying is protected:** build mode is unavailable while you have a timer running, and edit sounds are muted for anyone currently Focusing.

## Checkpoint 4: Leaves (earned by studying)

**Earning:** written to `village_leaves_ledger` when a focus session ends. A session only counts if it passes the valid-timing rules (SPEC §8.2).

| Source | Amount (starting suggestion; confirm in Checkpoint 0) |
|---|---|
| Valid focus session, solo | 1 Leaf per 5 focus minutes |
| Valid focus round in a group session | +20% bonus |
| First valid session of the day | +5 |
| Village goal reached (Checkpoint 8) | +30 to each member who contributed 60+ minutes |
| Daily cap | 60 Leaves from focus per day |

- Anti-gaming:
  - Sessions in which the user was Away (idle) for more than 20% of the time earn nothing.
  - Overlapping sessions count once.
  - A session started on desker.dev (not in the village) **also** earns Leaves. Studying is studying.
- Balance = sum of the ledger, computed and cached; never a mutable number.
- **HUD:** a small leaf counter. A soft "+6 🍃" floats up when Leaves are earned, after the session ends, never during focus.
- **Wallet panel:** balance, this week's earnings, history (date, reason, amount).
- desker.dev shows the Leaves balance on the profile/kodama area, so the planner and village feel like one product.

**Tests:**
- Earning rules
- Cap
- Away penalty
- Overlap
- Ledger idempotency (a session can never pay twice)

## Checkpoint 5: Shop and ownership

- **Shop** (from the decor tray or the wardrobe): every buyable item with its price.
  - Buying writes a negative ledger entry + `village_cosmetic_owned` (or an inventory count for decor), in one database transaction.
  - Show "You'll have X Leaves left" before confirming.
- **Ownership rules:**
  - Decor you buy is **yours**. You can place it in any village where you have build permission.
  - "Put away" returns it to your inventory.
  - If you leave or are removed from a village, your placed items return to your inventory. The village gets a gentle note: "Mai's lantern went home with her."
  - The owner can't "steal" items. They can only ask the item's owner to put it away, or put it away themselves, which returns it to its owner.
  - **Village items:** members can *gift* an item to the village. It then belongs to the village and stays if they leave. Village items are listed separately in the tray.
- Prices are in Leaves only. There is no money anywhere in the shop.

## Checkpoint 6: Kodama customisation (wardrobe)

- `village_kodama_appearance`: base (3 shapes), colour (12, palette swap), face (8 expressions), and equipped slots:
  - head (beanie, flower crown, headphones, graduation cap…)
  - neck (scarf, bow, bell)
  - held (book, tea cup, lantern, pencil)
  - back (tiny backpack, cape, leaf wings)
- **Growth stage** from Desker (seedling → sprout → sapling → …) changes the sprite subtly (the leaf on top grows, size +1 px per stage). Show it on the name tag hover.
- **Wardrobe panel** (⋯ → Wardrobe, or click your own kodama):
  - Live preview, rotatable through 4 directions
  - Owned items + shop items with prices
  - Equip / unequip
  - "Randomise" for fun
- Appearance is part of the member's data in `welcome` and broadcast on change. Sprites are composited client-side from layered sheets: base + colour swap + face + slot layers, all in the same frame layout.
- Some items are earned, not bought (e.g. "Night Owl lantern: finish 10 valid sessions after 21:00", "Early Bird scarf: 10 sessions before 08:00"). They're shown locked, with how to earn them.
- desker.dev shows the same kodama appearance wherever the kodama appears (Today page, Kodama chat), so the two products stay one character.

## Checkpoint 7: Templates and seasons

- **Two more templates,** same zone structure and rules, different mood:
  - **Tea House:** wooden interior, sliding doors, tatami library, a tea garden
  - **Night Library:** tall shelves, warm lamps, starry windows, rain instead of snow

  Generate them with the same map script. On creation, owners pick one; an existing village can switch template only via owner confirm (placements that no longer fit go back to inventory).
- **Seasons:**
  - Each template has winter / spring / exam-week tile variants (swapped at render time without changing the map).
  - A village setting chooses Auto (from an academic calendar) or a fixed season.
  - The academic calendar is a config with default Chulalongkorn-style semester dates that I'll edit; exam weeks switch to the "exam week" variant (warmer lights, a few motivational banners, slightly calmer music).
- Seasonal decor appears in the shop only during its season. Owned items stay owned forever.

## Checkpoint 8: Village focus goal and the village tree

- **Owner/admin sets a monthly goal:** total valid focus minutes in this village (suggested by member count: 20 h × active members).
- **A tree in the Plaza** grows through 5 stages as progress rises (0, 25, 50, 75, 100%). The Board shows a progress bar: "71 of 100 hours together".
- **At 100%:**
  - A celebration: soft snow-sparkle, a chime, the Kodama NPC cheers in a bubble
  - Every contributor with 60+ minutes gets the Leaves reward
  - The village unlocks a goal-only decor item for its Village items
- **No leaderboards, no shame.** The goal panel shows contributors as kodama icons, sorted alphabetically, not by minutes.
- History: past months' trees are kept as small saplings in the Garden ("October 2026 · 112 h").

## Demo script
1. Four friends in an existing village each earn Leaves from a group session.
2. Two of them decorate at the same time: one places lanterns along the path, the other builds a cosy corner in the Lounge. Try to block the Library path; it should refuse.
3. Someone gifts a kotatsu to the village.
4. Everyone opens the wardrobe and buys or equips something; check it shows on desker.dev's Today page too.
5. Set a small village goal, run sessions until it's reached, and watch the tree celebrate.
6. Link LINE, ask the bot `who`, and receive a "question answered" notification there.
7. Share a session card to an Instagram story from a phone.
